11 / 15 3 — RBAC

Holding Admin vs Subsidiary Admin

Key differences between the God Mode cross-tenant admin and the subsidiary-scoped admin.

👑 Holding Admin (God Mode)

  • See ALL companies' data across tenants
  • Switch active company via CompanyContext
  • Access /holding page (manage subsidiaries)
  • RLS bypass: get_auth_role() = 'holding_admin'
  • All admin powers across ALL tenants
  • Can create new subsidiary companies

🔑 Subsidiary Admin

  • See ONLY own company's data
  • Cannot switch companies
  • Cannot access /holding page
  • RLS enforced: company_id = own company
  • Full admin powers within own tenant only
  • Cannot create or manage subsidairies

15 / 15 5 — CODE AUDIT

Identified Issues & Risks

Potential problems found during the full codebase reverse-engineering. These should be reviewed and addressed.

⚠️ RISK

Dual Notification Triggers

Two AFTER UPDATE triggers (notify_on_status_change and notify_status_change) fire on the same event, potentially producing duplicate notifications for a single status change.

⚡ INCONSISTENCY

PIC Column Transition

The pic (text) column coexists with pic_ids (uuid[]). Some triggers still use name-based PIC lookups, while newer RPCs use UUID arrays — creating fragile joins.

ℹ️ DEAD-END

Unused Status Values

Internal Review and Waiting Approval exist in the CHECK constraint but no code path transitions into them — dead-end states.

⚡ INCONSISTENCY

Missing resolution_type in carry_over_plan

The standalone carry_over_plan RPC doesn't set resolution_type = 'carried_over' on the parent plan (unlike the Resolution Wizard RPC).

✅ FIXED

Multi-Tenant Settings Lookup

Original RPCs hardcoded id=1 for settings. Fixed in migration 20260225100000 — now uses company_id. However, grade_action_plan may still need audit.

⚡ MISSING

Role Check Constraint Dropped

The profiles_role_check constraint was dropped to allow holding_admin but never recreated — no validation on role values.
